# Deploying CaseBench

The app ships as **one Docker container**: Express serves both `/api/*` and the
built React app. The database is TiDB Cloud, so no database runs in the
container.

---

## Option A - Render (free, no credit card)

> The **free** instance type does not require a payment method. If Render asks
> for payment, you picked a paid instance or a persistent disk. Go back and
> choose **Free**.

### 1. Push the code

Everything must be on GitHub before Render can build it.

```powershell
cd "C:\Users\BS-24\Documents\Default Project"
git add -A
git commit -m "Fix login, rate limiting, MUI v9 grid, pagination; add Render blueprint"
git push origin main
```

### 2. Create the Blueprint

1. Render Dashboard -> **New +** -> **Blueprint**.
2. Pick the `RNNLEGAL` repository.
3. Render reads `render.yaml` at the repo root and shows one service, `casebench`.
4. Fill in the prompted secrets (`DB_*`, optionally Cloudinary / email) and apply.

`JWT_SECRET` is generated by Render. `CLIENT_URL` is not needed: the server uses
Render's `RENDER_EXTERNAL_URL` automatically.

### 3. Wait for the first build

The Docker build runs `npm ci` twice (client + server) and takes a few minutes.
When it finishes, open the service URL. The first request after 15 minutes of
inactivity takes ~30-60 s (free instances sleep).

### 4. Verify

- `https://<your-service>.onrender.com/api/health` returns JSON with
  `"environment":"production"`.
- Log in with an admin account.
- Create a client, a case, and a task.

## Option B - Hugging Face Spaces (fallback, no card at all)

Use this if Render keeps demanding payment.

1. Create a Space -> **Docker** -> **Blank**.
2. Push this repository to the Space's git remote (or upload the folder).
3. The Space needs the Dockerfile at its root. Either point the Space at a
   Dockerfile that `COPY`s `case-management-system/`, or set the Space's
   `README.md` metadata `sdk: docker` with `app_port: 5000`.
4. Add the same environment variables as Option A under
   **Settings -> Variables and secrets**.
5. Set `CLIENT_URL=https://<user>-<space>.hf.space` (Spaces does not set
   `RENDER_EXTERNAL_URL`).

## Environment variables

| Variable | Required | Value |
| --- | --- | --- |
| `NODE_ENV` | yes | `production` |
| `PORT` | yes | `5000` |
| `DB_HOST` | yes | TiDB Cloud host |
| `DB_PORT` | yes | `4000` |
| `DB_USER` | yes | TiDB user |
| `DB_PASSWORD` | yes | TiDB password |
| `DB_NAME` | yes | `case_management` |
| `JWT_SECRET` | yes | 32+ random chars (Render generates it) |
| `JWT_EXPIRE` | yes | `7d` |
| `RATE_LIMIT_MAX_REQUESTS` | recommended | `3000` |
| `CLIENT_URL` | auto on Render | public URL of the service (comma-separated if several) |
| `CLIENT_PORTAL_URL` | auto | `<CLIENT_URL>/client-portal` |
| `EXTRA_ORIGINS` | yes | comma-separated custom domains allowed by CORS, e.g. `https://rnnlegal.in,https://www.rnnlegal.in` |
| `CLOUDINARY_*` | optional | blank = uploads saved to local disk |
| `EMAIL_*` | optional | password-reset emails |
| `ECOURTS_*` | optional | eCourts lookups |

Secrets are entered in the host's dashboard. Never commit `server/.env`.

## Known limitations of the free tier

1. **Uploaded documents are ephemeral.** Free Render has no persistent disk, so
   files in `server/uploads` disappear on every redeploy/restart. Fix: create a
   free Cloudinary account and set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`,
   `CLOUDINARY_API_SECRET`. No code change needed.
2. **The service sleeps** after 15 minutes idle. The first request afterwards
   is slow, and cron jobs (hearing reminders) pause while it sleeps.
3. **Custom domain** is configured: `rnnlegal.in` points at this service. Any
   new domain must also be added to `EXTRA_ORIGINS` in `render.yaml`, otherwise
   the browser gets CORS 500s and the page renders blank.
4. **Free plan = 512 MB RAM.** Fine for this app; heavy document previews may
   be slow.

## Rollback

Render keeps every deploy. Dashboard -> service -> **Deploys** -> pick a previous
one -> **Redeploy**.
